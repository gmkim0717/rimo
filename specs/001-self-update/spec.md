# 001 · 자동 업데이트 (Self-Update)

상태: **확인됨 (2026-09-05), plan 진행 가능**
헌법 근거: 제4조(MVP 정의 — 자동 업데이트는 재생 기능보다 우선), 제3조(시간 예산 ≤ 20시간)

---

## 1. 무엇을 만드는가

앱이 스스로 새 버전을 확인하고, 있으면 설치 파일을 미리 받아둔 뒤, 사용자에게 설치 확인만 요청하는 기능.
개발자는 열 대의 박스를 한 번도 직접 만지지 않고 버그 수정판을 배포할 수 있어야 한다.

## 2. 왜 지금 만드는가

앱스토어에 올리지 않으므로 업데이트 통로가 없다. 열 대 설치 후 버그가 나오면 집집마다 다시 찾아가야 하고, 그 방식은 두 번 반복하기 전에 무너진다.
그래서 이 기능은 재생 기능보다 먼저 완성되어 있어야 하고, **첫 배포판에 반드시 포함**된다.

## 3. 사용자

- **시청자(열 명)**: 리모컨만 있다. 업데이트가 있다는 사실을 몰라도 되고, 설치 확인 버튼 하나만 누르면 된다.
- **개발자(1명)**: 새 버전을 정해진 장소에 올리고 정보 한 줄을 바꾸는 것으로 배포가 끝나야 한다.

## 4. 범위

### 포함

- 앱 시작 시 새 버전 확인 (실행 중 주기적 재확인은 하지 않음)
- 새 버전이 있으면 배경에서 조용히 설치 파일 다운로드
- 다운로드 완료 후 사용자에게 설치 확인 요청
- 확인/거절에 따른 후속 동작
- 모든 실패 상황에서 사용자를 방해하지 않고 조용히 처리
- 사용자에게 보이는 문구는 한국어 / 중국어 / 영어 세 가지를 제공하고, 앱의 언어 설정에 따라 표시
- 개발자용 배포 절차 문서 (`docs/release.md`)
- 앱이 아직 존재하지 않으므로, 이 기능을 담을 **최소한의 앱 골격** (실행하면 빈 화면이 뜨는 수준)

### 제외 (backlog)

- 실행 중 주기적 재확인 (박스를 며칠 켜두는 경우 다음 재실행까지 업데이트를 못 받음 — 알고 감수함)
- 이전 버전으로 되돌리기
- 설치 후 앱 자동 재실행
- 변경 내역 화면에 보여주기 (정보 파일에는 넣되 첫 판에서는 표시하지 않음)
- 언어를 바꾸는 **설정 화면** 자체. 이 기능은 언어 값을 읽어 문구를 고르는 것까지만 담당한다. 설정 화면은 사용자가 처음으로 무언가를 입력하는 화면(002, m3u 주소 입력)에 함께 만든다. 그 전까지는 아래 FR-10의 기본 규칙으로 언어가 정해진다
- 특정 사용자에게만 먼저 배포하기 (단계적 배포)
- "지금 업데이트 확인" 수동 버튼

## 5. 동작 시나리오

### S1. 정상 흐름

1. 사용자가 앱을 켠다.
2. 앱은 화면을 정상적으로 띄우면서 동시에 배경에서 새 버전이 있는지 확인한다. 이 확인은 앱 시작을 지연시키지 않는다.
3. 새 버전이 있으면 배경에서 설치 파일을 받는다. 화면에는 아무것도 뜨지 않는다.
4. 다운로드가 끝나면 설치 확인 안내가 뜬다. 안내에는 "새 버전 x.y가 준비되었습니다"와 **[지금 설치] / [나중에]** 두 선택지만 있다.
5. [지금 설치]를 누르면 시스템의 설치 확인 절차가 시작된다. 사용자가 거기서 확인하면 설치되고 앱은 종료된다. 사용자가 앱을 다시 켜면 새 버전이다.

### S2. 사용자가 미룬 경우

- [나중에]를 누르면 안내가 사라지고, **이번 실행 중에는 다시 묻지 않는다.**
- 받아둔 설치 파일은 보관한다.
- 다음에 앱을 켤 때 (다시 받지 않고) 바로 설치 안내를 띄운다.

### S3. 시청 중에 다운로드가 끝난 경우

- 영상이 재생되고 있으면 안내를 바로 띄우지 않는다. 사용자가 채널 목록 등 재생 화면 밖으로 나온 시점에 띄운다.
- 이번 실행에서 그 시점이 오지 않으면 다음 실행 시 S2와 같이 처리한다.


### S4. 실패 흐름 (모두 조용히)

| 상황 | 동작 |
|---|---|
| 네트워크 없음 / 서버 응답 없음 | 아무것도 하지 않음. 다음 실행 때 다시 시도 |
| 업데이트 정보가 깨져 있거나 형식이 다름 | 무시. 다음 실행 때 다시 시도 |
| 서버 버전이 현재 버전과 같거나 낮음 | 아무것도 하지 않음 |
| 다운로드 도중 끊김 | 재시도 간격을 점점 늘리며 재시도, 최대 5회. 그래도 실패하면 이번 실행에서는 포기. 다음 실행 때 처음부터 다시 |
| 받은 파일이 손상됨 (예상과 다름) | 파일 폐기, 안내하지 않음. 다음 실행 때 다시 받음 |
| 저장 공간 부족 | 다운로드 시작하지 않음 |
| 시스템 설치 절차에서 사용자가 취소 | S2와 동일하게 처리 (다음 실행 때 다시 안내) |
| 시스템이 설치를 거부 (서명 불일치, 버전 번호 역행 등) | 파일 폐기, 안내하지 않음. 이는 개발자 배포 실수이므로 개발자가 알아내야 한다 |

어떤 경우에도 **오류 대화상자를 띄우지 않고, 앱이 죽지 않는다.**

## 6. 기능 요구사항

- **FR-1** 앱은 시작할 때 한 번, 개발자가 관리하는 공개 주소에서 업데이트 정보를 가져와 현재 버전과 비교한다.
- **FR-2** 업데이트 정보에는 최소한 다음이 들어간다: 버전 번호(비교용 정수), 버전 이름(표시용), 설치 파일 주소, 설치 파일의 무결성을 확인할 수 있는 값, 변경 내역(첫 판에서는 미표시).
- **FR-3** 새 버전이 있으면 설치 파일을 배경에서 내려받는다. 다운로드 중 화면에 어떤 표시도 하지 않는다.
- **FR-4** 내려받은 파일은 무결성을 확인한 뒤에만 설치 안내 대상이 된다.
- **FR-5** 설치 안내는 리모컨 방향키 + 확인 + 뒤로가기만으로 조작 가능해야 한다. 뒤로가기는 [나중에]와 같다.
- **FR-6** [나중에] 이후 같은 실행 중에는 다시 묻지 않는다. 다음 실행에서는 다시 받지 않고 바로 안내한다.
- **FR-7** 설치가 완료되었거나, 더 새로운 버전의 파일이 받아졌으면 이전 설치 파일을 삭제한다.
- **FR-8** 업데이트 확인 요청에는 사용자를 식별할 수 있는 어떤 정보도 포함하지 않는다 (헌법 제5조). 서버가 알게 되는 것은 요청이 왔다는 사실뿐이다.
- **FR-9** 업데이트 기능의 어떤 실패도 앱의 다른 기능에 영향을 주지 않는다.
- **FR-10** 설치 안내의 모든 문구는 한국어 / 중국어(간체) / 영어로 제공한다. 표시 언어는 앱의 언어 설정값을 따른다. 설정값이 아직 없으면 박스의 시스템 언어를 따르고, 시스템 언어가 세 가지 중 어느 것도 아니면 영어를 쓴다. 앱 언어 설정값은 다른 기능(002 이후)도 같은 값을 읽어 쓴다.

## 7. 개발자(운영) 요구사항

- **OR-1** `docs/release.md`에 배포 절차를 적는다: 버전 번호 올리기 → 서명된 설치 파일 만들기 → 파일 올리기 → 업데이트 정보 갱신하기 → 박스 한 대에서 확인하기.
- **OR-2** 버전 번호(정수)는 배포마다 반드시 증가한다. 같거나 낮으면 시스템이 설치를 거부한다.
- **OR-3** 서명 키는 생성 즉시 다른 장소에 백업하고, 백업 위치를 `docs/release.md`에 기록한다. 키를 잃으면 열 명 전원이 삭제 후 재설치해야 한다.
- **OR-4** 모든 배포판은 같은 키로 서명한다.

## 8. 비기능 요구사항

- 업데이트 확인 때문에 첫 화면이 늦게 뜨면 안 된다. 확인은 화면 표시와 동시에 배경에서 진행한다.
- 다운로드가 재생 화질에 영향을 줄 수 있다는 점은 감수한다 (첫 판에서는 대역폭 제한 안 함). 문제가 되면 명단의 사람들에게 물어본다.
- 이 기능 구현은 20시간을 넘기지 않는다. 넘으면 범위를 잘라낸다.

## 9. 수용 기준

실기기(가장 약한 박스)에서 확인:

- **AC-1** 낮은 버전을 설치하고 서버에 높은 버전을 올린 뒤 앱을 켜면, 화면은 즉시 뜨고, 잠시 후 설치 안내가 뜬다. 리모컨 방향키로 [지금 설치]/[나중에] 사이를 이동할 수 있고 포커스가 눈에 보인다.
- **AC-2** [지금 설치] → 시스템 설치 확인 → 설치 완료 → 앱 재실행 시 새 버전이다.
- **AC-3** [나중에]를 누르면 안내가 사라지고 앱을 계속 쓰는 동안 다시 뜨지 않는다. 앱을 끄고 다시 켜면 즉시(다운로드 없이) 안내가 뜬다.
- **AC-4** 뒤로가기 키는 [나중에]와 같이 동작한다.
- **AC-5** 서버에 현재와 같은 버전이 있으면 아무 일도 일어나지 않는다.
- **AC-6** 네트워크를 끊고 앱을 켜면 아무 오류도 보이지 않고 앱은 정상 동작한다.
- **AC-7** 업데이트 정보 파일을 고의로 깨뜨려 올려도 앱은 정상 동작한다.
- **AC-8** 설치 파일 주소를 잘못된 파일로 바꿔 올리면 (무결성 불일치) 안내가 뜨지 않고 앱은 정상 동작한다.
- **AC-9** 영상 재생 중에 다운로드가 끝나면 재생 화면에는 안내가 뜨지 않고, 목록으로 나왔을 때 뜬다.
- **AC-9a** 박스 시스템 언어를 중국어로 바꾸면 안내가 중국어로, 한국어로 바꾸면 한국어로, 일본어로 바꾸면 영어로 뜬다.

자동 테스트로 확인:

- **AC-10** 버전 비교 규칙 (높음/같음/낮음, 정보 누락, 형식 오류)
- **AC-11** 업데이트 정보 해석 (정상, 필드 누락, 형식 오류, 빈 응답)
- **AC-12** 재시도 규칙 (횟수 상한, 간격 증가)
- ~~AC-12a 언어 선택 규칙~~ → 삭제 (2026-09-05). 언어 선택은 플랫폼 리소스 해석에 위임되어 우리 코드가 없다. AC-9a 실기기 확인으로 대체.

문서:

- **AC-13** `docs/release.md`가 존재하고 OR-1~OR-4를 담고 있다.

## 11. 알려진 위험

- **시스템 설치 확인 화면이 리모컨으로 조작되지 않는 박스가 있을 수 있다.** 이 화면은 우리가 만드는 것이 아니라 시스템 것이다. 열 대 중 하나라도 그러면 그 박스는 다른 방법이 필요하다. 첫 배포 전에 모든 기종에서 AC-2를 확인한다.
- 일부 박스는 "알 수 없는 출처 설치" 허용을 앱마다 따로 요구한다. 첫 설치 시 한 번 켜줘야 할 수 있고, 이는 `docs/release.md`의 최초 설치 절차에 적는다.
